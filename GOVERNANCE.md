# Governance

Berrie Market Infrastructure is currently a maintainer-led project.

## Maintainers

Maintainers are responsible for scope, public API decisions, releases, security
response, and contributor access. Current maintainers are listed through the
repository's GitHub permissions rather than duplicated in this document.

## Decisions

Routine changes are decided through pull request review. Public API changes and substantial design decisions should begin with an issue and record the reasoning before implementation.

Decisions are based on:

- usefulness across independent market-data systems
- predictable behavior under load
- a small and maintainable API
- dependency and security cost
- compatibility with the project's published boundaries

## Releases

Only maintainers may publish releases. A release must have a documented scope, passing checks, an updated changelog, and no known unresolved release-blocking security issue.

## Becoming a maintainer

Contributor access is earned through sustained, constructive work and sound review judgment. The maintainers may add collaborators as the project develops; no automatic tenure or contribution threshold is promised.

## Conflicts

Maintainers should disclose material conflicts that could affect a technical or
security decision. Project governance applies only to this public repository.
