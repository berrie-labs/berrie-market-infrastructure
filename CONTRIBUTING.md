# Contributing

Thank you for considering a contribution.

This project is intentionally narrow. Contributions should improve reusable market-data infrastructure without introducing product-specific behavior, trading logic, or hidden network dependencies.

## Before opening a pull request

1. Search existing issues and pull requests.
2. Open an issue before proposing a new public API or a substantial design change.
3. Keep the change focused on one problem.
4. Add or update tests for behavior changes.
5. Update documentation when an API or observable behavior changes.

## Pull requests

A useful pull request explains:

- the problem being solved
- the chosen behavior and its limits
- alternatives considered
- how the change was verified

Avoid unrelated formatting changes or broad rewrites. Maintainers may ask for a smaller patch when a change is difficult to review safely.

## Compatibility

The repository is pre-release. Compatibility guarantees begin only when a package documents them. Breaking changes must still be explicit in the pull request and changelog.

## Conduct and security

Participation is governed by [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Do not disclose a suspected vulnerability in a public issue; follow [SECURITY.md](SECURITY.md).
